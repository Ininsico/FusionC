# FusionC DSL Specification (v1)

FusionC compiles a small tensor-pipeline DSL into fused CUDA C for NVIDIA Pascal
(`sm_61`, GTX 1050 Ti / GTX 1070 class consumer GPUs).

The DSL describes **inference graphs** for transformer-shaped workloads. The compiler
expands composite ops into a primitive DAG, fuses the DAG under Pascal-specific
resource heuristics, and emits CUDA C.

---

## 1. Lexical structure

| Element | Syntax |
|---|---|
| Line comment | `// ...` or `# ...` (to end of line) |
| Block comment | `/* ... */` (non-nesting) |
| Identifier | `[A-Za-z_][A-Za-z0-9_]*` |
| Integer literal | `[0-9]+` |
| Float literal | `[0-9]+\.[0-9]+([eE][-+]?[0-9]+)?` or `[0-9]+[eE][-+]?[0-9]+` |
| Keywords | `const`, `dtype`, `store`, `accum`, `input`, `param`, `fp16`, `fp32` |
| Punctuation | `= ; , : ( ) [ ] ->` |

Whitespace and comments are skipped. Keywords are case-sensitive and lowercase.

## 2. Grammar

```
program     ::= decl_list stmt_list

decl_list   ::= decl_list decl
              |                                  /* empty */

decl        ::= CONST IDENT EQ INT SEMI
              | DTYPE datatype STORE datatype ACCUM SEMI
              | tensordecl SEMI

datatype    ::= FP16 | FP32

tensordecl  ::= (INPUT | PARAM) IDENT COLON datatype dims
dims        ::= '[' expr_list ']'

stmt_list   ::= stmt_list stmt
              |                                  /* empty */

stmt        ::= IDENT EQ stage_list SEMI
stage_list  ::= stage_list ARROW stage
              | stage
stage       ::= opcall
              | IDENT

opcall      ::= IDENT '(' arglist ')'
arglist     ::= expr_list
              |                                  /* empty */
expr_list   ::= expr_list ',' expr
              | expr
expr        ::= INT
              | FLOAT
              | IDENT
              | opcall
```

The parser is generated by CUP (`src/main/cup/Parser.cup`) and fed by the JFlex
scanner (`src/main/jflex/Scanner.flex`) running in `%cup` mode: the scanner returns
`java_cup.runtime.Symbol` objects carrying `(type, line, column, value)`.

## 3. Declarations

### 3.1 Compile-time constants

```
const SEQ = 64;
const D   = 256;
```

Constants may be used in tensor dimensions. They must be declared before use.

### 3.2 Numeric policy

```
dtype fp16 store fp32 accum;
```

Sets the default **storage** dtype (what lives in global/shared memory) and the
**accumulate** dtype (arithmetic precision in registers). `fp16 store fp32 accum`
is the default and the recommended policy for consumer Pascal, whose FP16
arithmetic rate is 1/64 of FP32 (see REPORT.md) — FP16 is used for *bandwidth*,
FP32 for *math*.

An individual tensor may override the default storage dtype in its own
declaration, which is what you want for bias vectors and normalisation gains:

```
param bias : fp32 [1024];
```

### 3.3 Tensors

```
input Q : fp16 [SEQ, D];      // graph input, produced by the host
param W1: fp16 [D, F];        // graph parameter, produced by the host
```

* `input` and `param` are both host-supplied (loaded from `.bin` by the generated
  harness). The distinction is documentation only, and is preserved in the IR.
* Dimensions are `expr`s: integer literals or previously declared constants.
* Tensors are row-major and contiguous; every tensor is 2-D in v1
  (batches are folded into the row dimension).
* `fp16` tensors are stored as IEEE-754 binary16 and are 2-byte aligned.

## 4. Pipelines

A pipeline is a chain of stages bound to a name. `->` is *sequential composition*:
each stage consumes the previous stage's result as its "subject" (its first
positional argument). A pipeline terminates with `;`.

```
out = attention(Q, K, V) -> MLP(W1, relu, W2, b1, b2);
```

The left-hand side name becomes the pipeline output tensor.

### 4.1 Primitive stages

| Stage | Signature | Semantics |
|---|---|---|
| `matmul(A, B)` | `[M,K] x [K,N] -> [M,N]` | Matrix multiply |
| `matmul_nt(A, B)` | `[M,K] x [N,K] -> [M,N]` | A·Bᵀ (used by attention scores) |
| `bias(X, b)` | `[M,N] x [N] -> [M,N]` | Row-broadcast bias add |
| `relu(X)` | `[M,N] -> [M,N]` | `max(0,x)` |
| `gelu(X)` | `[M,N] -> [M,N]` | tanh approximation of GELU |
| `scale(X, k)` | `[M,N] x float -> [M,N]` | Multiply by scalar |
| `add(A, B)` | `[M,N] x [M,N] -> [M,N]` | Elementwise add (residual) |
| `softmax(X)` | `[M,N] -> [M,N]` | Row-wise softmax over the last dim |
| `layernorm(X, g, b)` | `[M,N] x [N] x [N] -> [M,N]` | Row-wise LayerNorm |

### 4.2 Composite stages

Composite stages are **macros**: the front end expands them into primitives before
fusion, so every fused kernel the back end produces is derived from the primitive IR.

| Stage | Signature | Expansion |
|---|---|---|
| `attention(Q,K,V)` | `[B,D] x [B,D] x [B,D] -> [B,D]` | `S = matmul_nt(Q,K) · (1/√D)` → `P = softmax(S)` → `O = matmul(P,V)` |
| `MLP(W1, act, W2)` | subject `X:[M,D]`, `W1:[D,F]`, `W2:[F,N]` | `H = act(matmul(X,W1))` → `Y = matmul(H,W2)` |
| `MLP(W1, act, W2, b1, b2)` | as above plus biases | `H = act(matmul(X,W1)+b1)` → `Y = matmul(H,W2)+b2` |

`act` is an identifier naming a unary activation (`relu` or `gelu`). The
attention scale `1/√D` is folded into the score GEMM as an epilogue attribute
rather than emitted as a separate op.

## 5. Semantics and type checking

* Shapes are inferred bottom-up; a shape mismatch is a compile error naming the
  offending stage (the compiler fails loudly rather than emitting wrong code).
* `softmax`/`layernorm` normalise over the **last** dimension.
* Unknown or unimplemented stage names are a hard error:
  `error: unsupported op 'conv2d' at line 12, column 8`.
* An op whose fused and unfused forms are both applyable is fine; an op that no
  emitter can handle is a hard error (`fail loudly`).

## 6. Worked examples

`examples/attention_mlp.dsl` — the reference workload from the project brief:

```
const SEQ = 64;
const D   = 256;
const F   = 1024;

dtype fp16 store fp32 accum;

input Q  : fp16 [SEQ, D];
input K  : fp16 [SEQ, D];
input V  : fp16 [SEQ, D];
param W1 : fp16 [D, F];
param b1 : fp32 [F];
param W2 : fp16 [F, D];
param b2 : fp32 [D];

out = attention(Q, K, V) -> MLP(W1, relu, W2, b1, b2);
```

`examples/mlp_wide_batch.dsl` — same graph with `SEQ = 512`, which raises the
fused-MLP grid above the occupancy floor so the GEMM→GEMM fusion is accepted
(the 64-row variant is *rejected* by the heuristic with a logged reason).

`examples/residual_block.dsl` — exercises LayerNorm, residual `add`, and GELU.

`examples/unsupported.dsl` — contains `conv2d(...)` and must fail loudly.

## 7. Command line

```
java -jar fusionc.jar --input examples/attention_mlp.dsl --fuse       -o build/out_fused.cu
java -jar fusionc.jar --input examples/attention_mlp.dsl --no-fusion  -o build/out_unfused.cu
```

* `--fuse` / `--no-fusion` — select the fused or one-kernel-per-op back end.
* `-o <file>` — write the generated CUDA C translation unit (kernels + host harness).
* `--decisions <file.json>` — write the fusion decision log.
* `--ir <file.txt>` — dump the annotated IR (op, shape, dtype, placement, deps).
* `--sm-count <n>` — target SM count used by occupancy heuristics (default 6 = GTX 1050 Ti).
* `--dump-ast` — dump the parsed AST (front-end debugging).
